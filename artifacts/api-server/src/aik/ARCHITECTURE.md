# Kids AI Studio — architecture

_Target state as of October 2026. The "as observed" diagram that preceded this
document is in the Humanity + AI Claude project (AI for Kids Hub on Azure)._

      │      │      └── Blob  sthumanityplusai / aik-media (private)
      │      │           pictures, songs, shots, movies, narration

## Why two apps

One container ran everything. That meant an events edit restarted the kids'
platform, a bug in either took down both, the marketing site's Google Ads
remarketing tag loaded on `/aiforkids/studio` (a COPPA exposure), and the
kids' platform scaled to zero in the middle of a club session because the
website was quiet.

`APP_ROLE` (see `../role.ts`) turns the same image into either half:

| | `site` | `kids` |
|---|---|---|
| Serves | website, blog, events, donations, author tools | `/aiforkids/*` pages and `/api/aik/*` only |
| Studio pages | 301 → `KIDS_ORIGIN` | here |
| `/api/aik` | 410 with the new origin | mounted |
| Google tag | yes, except under `/aiforkids` | never |
| Stripe webhook, seeding, newsletter | yes | no |
| Scale | 0–3 | **1**–3 (no cold start when a class signs in) |

Both read the same Postgres server. The Studio's tables are all `aik_*`; a
later step can move them to their own database without a code change beyond
`DATABASE_URL`.

## The request pipeline (unchanged in spirit, finished in practice)

```
order → validate → PII catcher → blocklist → Content Safety + Prompt Shields
      → model → output screening → (code scan | picture screening | frame screening)
      → artifact → facilitator approval for anything with generated media
```

What changed is what the studios deliver at the end of it:

| Studio | Before | Now |
|---|---|---|
| Story Maker | a six-panel comic script to draw yourself | a picture book: cover + 6 illustrated pages, same hero throughout, narrated, flip-book viewer, PDF (`book.ts`, `bookpdf.ts`) |
| Video Maker | a storyboard and, sometimes, one portrait clip | three Sora shots cut behind a title card with narration into one landscape MP4; every frame screened (`movie.ts`, `ffmpeg.ts`) |
| Music Maker | a tune that ignored the words | a song that sings the child's own lyrics, with a download |
| Game Maker (children) | one model call, shipped unverified | plan → build → run → repair, same checker the Hub uses (`forge.ts` light mode) |

Change requests are cheap by design: a book whose scenes did not change keeps
its pictures and narration (`buildBook` compares page by page), so "make the
ending funnier" costs one or two pictures, not seven.

## Media

Generated bytes no longer live in Postgres rows. `media.ts` writes them to the
private `aik-media` blob container as `r<requestId>/<name>` and the artifact
keeps `aik://` references. They are served only through
`/api/aik/artifacts/:id/media/:dir/:file`, which applies the artifact's own
access check and refuses any name the artifact does not reference. Nothing in
that container is reachable without a Studio session. Without a configured
store (local work), media stays inline as `data:` URIs and every reader
accepts both shapes.

## Guardrails, in one place

- **Who**: class code + nickname + PIN, consent recorded before sign-in,
  sessions that expire, ticket and chat-turn limits per session, cost
  ceilings per child per day and per organization per month.
- **Words in**: PII catcher, blocklist, Content Safety text analysis, Prompt
  Shields. Fail closed in production when screening is unreachable.
- **Words out**: output screening on every model reply, REDIRECT handling,
  links stripped, homework helper never answers.
- **Pictures and video**: every generated image through Content Safety image
  analysis; every movie pulled apart at one frame per second and each frame
  screened; a single hit blocks the whole piece.
- **Code**: games and micro:bit programs parsed and run in a sandbox before
  a child sees them; network, storage, dialogs and escapes forbidden.
- **People**: anything with generated media waits for a facilitator. The
  review queue, the live feed and the audit log make that gate usable.
- **Platform**: no third-party scripts on the kids host; `Referrer-Policy:
  no-referrer`; `noindex` on the Studio, Hub and dashboard; secrets by Key
  Vault reference only; Azure OpenAI optionally by managed identity
  (`AIK_AZURE_USE_IDENTITY`), blob storage by managed identity.

## What to revisit next

1. **Database**: private endpoint for `pg-humanityplusai` and its own `aik`
   database; today it is public with an allow-all-Azure rule.
2. **Entra ID for every Azure AI call**: Content Safety and Speech still use
   keys; both resources accept managed identity.
3. **Cost ceilings in the ledger**: `AIK_CEILING_*` are enforced per request;
   a book is one request and seven pictures. Count generations, not orders.
4. **Observability**: a dashboard over `aik_audit` and the Container App
   logs (blocked rate, approval latency, generation failures by provider).
5. **Second region**: Sora and FLUX live on one Foundry resource in East US 2;
   a second deployment elsewhere would let `movie.ts` and `book.ts` fail over
   the way text already does.
